# Implementation Context: Add /ping Endpoint

This context bundle provides the necessary information to implement a `/ping` endpoint that returns `pong`.

## 1. Test Command
`pytest --cov=app`

## 2. Build Command
`pip install -e '.[dev]'`

## 3. Relevant Code Snippets

### app/main.py: Existing Utility Endpoints
```python
@app.get("/health")
async def health_check():
    return {"status": "healthy"}


@app.get("/")
async def root():
    return {
        "service": "payment-processing",
        "version": "0.1.0",
        "docs": "/docs",
    }
```

### tests/test_payments.py: Testing Pattern with AsyncClient
```python
import pytest
from httpx import AsyncClient


@pytest.mark.asyncio
async def test_get_payment(client: AsyncClient, payment):
    response = await client.get(f"/payments/{payment['id']}")
    assert response.status_code == 200
    assert response.json()["id"] == payment["id"]
```

## 4. Test Patterns
Existing tests use `pytest` with `pytest-asyncio`. The `client` fixture provides an `httpx.AsyncClient` already configured to interact with the FastAPI app.
Tests should:
- Use `@pytest.mark.asyncio`.
- Use the `client` fixture.
- Assert on `status_code` and JSON response content.

## 5. Files to Modify/Create
- **Modify** `app/main.py`: Add the `/ping` endpoint registration.
- **Create** `tests/test_main.py`: Add a test case for the `/ping` endpoint (and optionally for `/` and `/health`).

## 6. Constraints and Gotchas
- **Async Endpoints**: All existing endpoints are `async`. The new `/ping` endpoint should also be `async`.
- **Response Format**: Existing utility endpoints in `main.py` return JSON objects. The `/ping` endpoint should follow this pattern, e.g., returning `{"ping": "pong"}`.
- **Dependency Overrides**: Tests rely on `app.dependency_overrides` and fixtures defined in `tests/conftest.py`. However, for a simple `/ping` endpoint that doesn't use the database, no special setup should be needed beyond using the `client` fixture.
